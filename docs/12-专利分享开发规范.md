# 12 - 专利分享开发规范

> 状态：生效中
> 更新日期：2026-08-03
> 配套文档：[11-专利分享功能设计与开发计划.md](11-专利分享功能设计与开发计划.md)

本规范约束 PatentLens 专利分享功能的所有后续实现、测试、导出和维护工作。如与旧的 Tauri 文档冲突，以根目录 `AGENTS.md`、`docs/00-ACTIVE-ARCHITECTURE.md` 和本规范为准。

## 1. 架构和代码边界

1. 专利分享是 Electron 功能；禁止修改、同步或新增 `src-tauri/` 实现。
2. `src/scripts/web-app.js` 不得新增任何行。分享功能的新状态、事件、渲染和工具代码必须位于 `src/scripts/app/share/`。
3. `src/web.html` 只负责声明入口容器、样式和按依赖顺序加载脚本；不得把业务逻辑写进内联脚本。
4. 对已有 renderer 全局变量的兼容访问必须集中到 `share-source-adapters.js` 或明确命名的 facade。领域模型、导出器和 UI 不得直接访问 `currentData`、`kanbanState`、`GPCache`、`_pdPatentCache`。
5. 新增前端资源后，必须检查 `package.json#build.files` 是否会打入 asar，并更新 `src/web.html` 中的版本参数。

## 2. 数据模型规则

1. 所有输入首先规范化为分享领域模型；禁止把 GP、dossier、Excel、OCR 原始对象直接传给模块渲染器。
2. 每个可编辑的基础字段必须保留 `value`、`source`、`sourceRef`、`capturedAt`、`confidence`、`reviewState`。
3. 导入操作创建快照。刷新来源必须由用户明确触发，并显示新增、修改、冲突和删除的差异。
4. 默认字段优先级为 `manual > excel > google_patents > dossier > pdf_text > ocr`；档案专属字段不参与无意义的跨来源覆盖。
5. 不同非空值构成冲突时，必须进入待确认队列；禁止通过数组顺序、最后写入或静默覆盖解决。
6. Excel 未映射列必须保留为自定义字段。自定义字段名、原始列名和行号应可追溯。

## 3. 输入和 OCR 规则

1. 只接受用户明确选择的 `.pdf`、`.xlsx`、`.xls`、`.csv` 文件；文件类型、大小、页数和工作表均须先校验。
2. PDF 与专利的自动匹配仅可给出建议。没有公开号/申请号的可靠依据时，必须要求用户确认。
3. 本地 PDF OCR 使用专用 `/api/share/ocr` 或等价的显式 Electron bridge；禁止伪造 Global Dossier URL 或文档 ID 调用既有案卷端点。
4. OCR 请求应复用现有 PaddleOCR-VL / GLM OCR 实现、超时和错误结构；默认并发最多 2 个任务，并支持取消。
5. 临时 PDF、Base64 和 OCR 结果不得被写入日志。默认不持久化原始 PDF；持久化 OCR 结果时应以文件哈希去重。
6. OCR 失败不应阻止 Excel、GP 或人工信息进入分享项目；失败原因需在来源卡中显示。

## 4. AI 与研发表达规则

1. AI 是可选增强，不得成为基础 HTML 导出的前置条件。
2. 每段 AI 输出必须存储生成时间、provider/model 标识、输入来源范围和审核状态。
3. 涉及 OCR/审查文档的 AI 模块必须校验引用 ID 存在；无有效来源的内容显示“待核验”，不得伪装为事实。
4. 模块可输出技术问题、技术手段、技术效果、关键参数、实施例和研发待验证问题；不得自动下达侵权、无效、可规避、授权概率等法律结论。
5. “研发启发”必须措辞为建议或问题，并允许用户编辑、删除和标记责任人；不得将模型推断与专利原文混为一谈。
6. 提示词、模型调用和失败重试必须复用现有 AI 配置，不得把 API Key 写入项目、HTML、缓存、异常或日志。

## 5. 模块配置规则

1. 模块 ID、名称、数据依赖、支持模式、`full/lite/off` 行为和最小输入条件必须集中在模块注册表中定义。
2. 预设只修改模块配置，不得删除原始数据或人工编辑内容。
3. 应用配置的优先级是：单篇覆盖 > 全局配置 > 预设默认值 > 注册表默认值。
4. 必要模块在数据缺失时应展示来源缺失提示；不得用 AI 填充未提供的事实性字段。
5. 自定义模块仅允许富文本、字段卡片和数据表三种声明式类型。禁止保存、导出或执行用户提供的 JavaScript、事件属性、iframe 或远端脚本。
6. 多篇比较模块必须标明比较口径、选择字段和缺失值；不得把不同公开文本版本当作同一口径而不提示。

## 6. 导出和安全规则

1. 分享 HTML 必须可离线打开，禁止依赖 CDN、在线字体、远端脚本或运行时 API。
2. 导出前必须进行敏感信息扫描。以下内容一律禁止写入：API Key、Token、Cookie、代理 URL、绝对本机路径、未选择的原始文件。
3. 用户文本、Excel 单元格和外部数据必须进行 HTML 转义；Markdown 必须经白名单净化；URL 仅允许 `https:` 协议。
4. 序列化至 `<script>` 的 JSON 必须转义 `<`、`>`、`&`、U+2028、U+2029，防止关闭标签和脚本注入。
5. 原始 PDF 默认不嵌入。选择嵌入时需显示文件大小估计、设置单篇/项目总上限、二次确认并提示分享权限。
6. 输出必须包含数据来源、检索/生成时间、AI 内容标识和“仅供技术沟通，不构成法律意见”的声明。

## 7. 性能和持久化规则

1. 分享项目使用独立 IndexedDB 仓库，与 `PatentCache` 隔离；从现有缓存导入时只读复制。
2. 大字段、OCR 块和 AI 输出按项目分片持久化，避免把大对象放入 localStorage。
3. 预览不可调用网络；渲染器应接收纯快照和纯配置，保证可重复输出。
4. 对 1、5、10 篇专利分别验证生成耗时、内存、HTML 大小和搜索/目录交互。超过上限时应给出可操作的瘦身建议。
5. OCR、AI 和 HTML 生成均应显示进度、可取消状态及可恢复的失败说明。

## 8. 测试、评审和提交规则

每个可合并的实现批次至少满足：

- 字段标准化、优先级和冲突处理的纯函数单元测试；
- Excel 表头识别、手工映射、重复行、自定义列的测试；
- OCR 成功、失败、取消、大小限制的接口/契约测试；
- 模块注册表、全局配置、逐篇覆盖和预设的测试；
- 导出 HTML 的离线性、转义/净化和敏感信息扫描测试；
- 一项 Electron smoke 场景：导入 → 配置 → 预览 → 保存；
- `npm run verify:web-app`，以及功能完整时的 `npm run verify:refactor:full`。

代码评审还应确认：

- 没有向 `web-app.js` 新增代码；
- 无 Tauri 新代码或 Tauri 依赖扩张；
- 新资源已经进入 electron-builder 打包清单；
- 分享快照没有意外修改既有档案缓存；
- HTML 不含敏感信息，且不依赖在线资源；
- AI 内容、人工内容和原始来源在 UI/导出中可区分。

建议按垂直切片提交，例如 `feat(share): add normalized project snapshot`、`feat(share): import spreadsheet mappings`、`feat(share): export offline html`。一个提交只能覆盖一个可验证能力，不混入无关格式化、旧 renderer 重构或 Tauri 修改。

## 9. 工作台界面扩展规则

1. 分享工作台不是新的 `searchMode`。入口必须使用独立选择器和独立生命周期，不能修改或扩展冻结 renderer 对 `.search-mode-btn` 的分支。
2. 工作台壳层、项目状态、来源适配、模块配置和每个子视图都应位于 `src/scripts/app/share/`。入口脚本只编排导航；业务逻辑不得回流到 HTML 内联脚本。
3. 工作台打开时可暂时隐藏旧结果 section，但必须记录并在关闭时恢复其原有可见性；不得清空当前 dossier、GP、OCR 或批量查询状态。
4. 子视图使用稳定 ID：`overview`、`sources`、`review`、`modules`、`insights`、`preview`、`export`。新增视图须在注册表中声明标签、顺序、前置条件和渲染函数。
5. 子视图在缺少前置数据时显示下一步操作，而不是隐藏导航或给出空白页。未来功能不可用时必须明确标为“待接入”。
6. 所有来自专利、Excel、OCR 或 AI 的文本一律以 `textContent` 或经过净化的渲染器写入 DOM；工作台壳层不得把外部字段拼接为未经转义的 `innerHTML`。
7. 关闭、切换旧搜索模式和新建项目均需有明确的状态转换。项目含有材料时，新建项目应要求确认，避免误丢失草稿。
