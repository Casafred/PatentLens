已实现：

## 3. 已落地的数据契约

### 项目

`PatentShareStore.getSnapshot()` 返回隔离深拷贝。项目当前形状：

```js
{
  schemaVersion: 1,
  id, name, createdAt, updatedAt,
  patents: [PatentRecord],
  sources: [{ id, patentId, type, label, capturedAt }],
  moduleConfig: {}
}
```

`PatentRecord` 至少含 `id`、`patentNumber`、`title`、`fields`、`claims` 和 `source`。基础字段以来源值表示：

```js
{
  value: "…",
  source: "manual | excel | google_patents | dossier | pdf_text | ocr",
  sourceRef: "可展示的来源说明",
  capturedAt: "ISO-8601",
  confidence: "high | medium | low",
  reviewState: "accepted | conflict | pending"
}
```

人工确认必须调用 `PatentShareStore.updatePatentField()`，它会覆盖该项目字段为 `manual` 值；不得回写来源缓存。未来的字段合并实现需要在该结构上补充候选值或冲突集合，并保留每个候选值的上述来源语义。

### 持久化

- 数据库：`patentlens-share`，版本 `1`。
- 对象仓库：`projects`（`id` 为 keyPath）和 `meta`（记录 `activeProjectId`）。
- 已实现 API：`initialize()`、`getPersistenceState()`、`getSnapshot()`、`newProject()`、`renameProject()`、`addPatent()`、`updatePatentField()`、`removePatent()`、`flush()`、`onChange()`。
- OCR/AI 未来可进独立对象仓库；不要把 PDF Base64、密钥、Cookie 或本机路径放入项目记录。

UI 在 `initialize()` 完成后才绑定事件，避免恢复项目与用户操作竞争。写入采用串行队列；需要在测试或窗口关闭路径等待落盘时调用 `flush()`。

## 4. 推荐后续切片

每一项单独提交并完整验证，避免将输入、导出和旧 renderer 重构混在同一 PR。

1. **XLSX/XLS 与映射确认**：复用 `share-spreadsheet-import.js` 的记录契约；补充工作表/标题行选择和用户可编辑的列映射，不引入不受打包管理的远端依赖。
2. **字段冲突审核 UI**：以 `share-field-merge.js` 的候选值渲染冲突队列，允许用户选择候选或输入人工值；导出前应统计未决冲突。
3. **PDF/OCR**：在 Electron 主进程增加独立、受大小限制、可取消的 `/api/share/ocr` 或显式 bridge，复用现有 OCR 引擎；原始 PDF 默认不落盘。
4. **模块注册表**：实现必要模块 S1–S5、非 AI 的 R1/R3/R7、预设、全局配置和逐篇覆盖；自定义模块只接收声明式 JSON。
5. **安全渲染与导出**：创建独立渲染器、sandbox iframe 预览、HTML 保存 bridge、离线资源检查、敏感信息扫描与转义测试。
6. **研发深度协作**：按实际数据质量接入 R2/R4/R5/R6/R8/R9 和可选 AI；所有 AI 内容必须带来源与人工审核状态。

## 5. Agent 协作规则

1. 一个 Agent/提交只做一个可验证的垂直切片；不要并发改同一分享文件。
2. 读取既有 GP、dossier、OCR 或缓存只能经 `share-source-adapters.js`（或新增的明确 facade）完成；适配器输出必须是复制后的分享快照。
3. UI 一律用 `textContent` 或经过白名单净化的渲染器写入外来文本；不要把专利、表格或 OCR 内容拼接为 `innerHTML`。
4. 任何导出不得包含 API Key、Cookie、代理地址、绝对本机路径、未经选择的文件或未净化 HTML。
5. 新增脚本必须在 `src/web.html` 的 `web-app.js` **之后**加载；检查 `package.json#build.files` 会将其打入 Electron 包。
6. 修改前后都检查 `git diff -- src/scripts/web-app.js`；该文件不允许新增行。
7. 每个切片至少新增相应单元测试，并运行：

```powershell
npm test
npm run verify:web-app
npm run verify:refactor:full
```

在受限环境中 Electron smoke 可能需要允许写入 Electron 缓存目录；这不是产品代码问题。
