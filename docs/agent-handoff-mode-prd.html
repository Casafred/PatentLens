Agent 转移模式（Agent Handoff Mode）

让没有 API 配额的同事，也能把 PatentLens 的全部 AI 工作流"接力"给外部免费 Agent

一键复制"指令 + 结构化上下文"到任意 Agent 聊天界面；审查 PDF 在交接面板直接拖入 Agent 上传区； 外部产出可回传归档。软件本身不发起任何外部 AI 请求，数据外发动作 100% 由用户手动完成。

1背景与目标

1.1 现状盘点：14 类 AI 能力全部依赖配额

对当前代码库的全面审视显示，PatentLens 的智能化能力已覆盖专利工作全链路，但每一类都依赖用户自配 API Key 或按量付费 Token：

1.2 问题：同事正在软件之外"裸奔"协作

❗
观察到的事实：API 资源集中在少数账号，多数同事没有可用 Key，软件内 AI 按钮对他们不可用。 他们转而在免费聊天界面（ChatGPT 免费版、Claude、Gemini、Kimi、豆包、DeepSeek 网页版、通义千问等）与 Agent 交互，而不是在软件内协作。

这种"软件外裸奔"产生五个具体痛点：

  1. 上下文手工拼凑，易错漏。专利号、权利要求、说明书、OCR 文本散落在不同 Tab，用户自行复制粘贴，漏段、错版、张冠李戴频发。
  2. 提示词各自为战，口径不统一。同一份审查意见，不同人问法不同，产出格式与分析深度无法对齐，团队知识无法沉淀。
  3. PDF 交接低效。审查文档要先下载到本地、改名、再上传聊天窗口；用户分不清该传哪几篇，文件名混乱。
  4. 产出回不到软件。外部 Agent 的分析结果停留在聊天记录里，无法进入 AI 分析 Tab、无法导出 Word、无法与标注/比对数据关联。
  5. 无交接追溯。无法回答"这份结论基于哪版 OCR、用了什么提示词、谁在什么时候交接的"。

1.3 产品决策

新增一个不消耗任何 API 配额的工作模式——Agent 转移模式。PatentLens 退身成为"上下文与指令的准备台"：

  • 把软件内原本要喂给 AI 的上下文按标准化结构打包，把任务指令按团队统一口径渲染，一键复制；
  • 把审查 PDF 归集到文件交接区，支持从软件原生拖出，直接放进任意 Agent 聊天窗口的上传区；
  • 外部产出通过回传回到软件归档，并与来源功能联动；
  • 全过程留交接台账，可追溯、可续聊、可复用。

1.4 目标（以可观察结果表述）

目标可观察的达成证据
零配额可用未配置任何 API Key 的用户，可在全部 AI 入口使用"交接给外部 Agent"完成任务准备，不出现任何配额报错
两次点击出指令从任一 AI 功能入口出发，≤2 次点击生成包含完整上下文的可粘贴指令
文件零下载中转审查 PDF 从交接面板直接拖入浏览器 Agent 上传区，无需用户先去下载目录找文件
口径统一同类任务所有用户拿到的指令模板一致、版本可查；模板支持团队统一维护
产出可回流外部 Agent 的回答可粘贴回对应交接单，并在来源功能模块中查看/导出
安全可控本模式不新增任何指向 AI 厂商的网络请求；每次外发均由用户手动粘贴/拖拽完成

2产品模型与状态机

2.1 核心对象定义（全文档唯一定义）

对象定义关键属性
交接单
Handoff Ticket		一次交接的完整载体，串联"准备→复制→文件→回传"全流程ticketId、来源功能、模板、上下文块清单、文件载荷清单、目标档案、状态、时间戳、回传记录
上下文块
Context Block		可独立勾选的最小上下文单元，每块带类型、来源、字符数与脱敏标记blockType、source、charCount、truncated、redacted
指令模板
Prompt Template		与软件内 AI 功能 1:1 对应的提示词骨架，含占位符与输出契约templateId、version、builtin/custom、body
目标 Agent 档案
Target Profile		一类外部聊天 Agent 的适配参数集合上下文上限、文件类型/大小限制、多文件支持、深度链接、备注
文件载荷
File Payload		交接单关联的本地文件（PDF / 合并 PDF / 文本附件）fileName、localPath、size、status（待导出/已导出/已失效）
交接台账

回传记录
Return Entry		用户粘贴回来的外部产出，与交接单一对一或一对多关联content、externalModel（可选填）、returnedAt

2.2 交接单状态机

草稿 draft—复制指令→ 已复制 copied—文件导出/拖出→ 已备料 prepared—粘贴回传→ 已回传 returned—用户归档→ 已归档 archived
任意状态 —用户作废→ 已作废 revoked（同时触发文件清理选项）
状态进入条件允许动作
draft从入口新建或手工建单编辑块/模板/目标档案、复制、作废
copied一键复制成功（剪贴板写入确认）重新复制、导出文件、编辑、作废
prepared至少一个文件载荷成功落盘到交接目录拖出文件、在文件夹显示、回传、作废
returned用户提交非空回传内容查看回传、发送到来源模块、再复制、归档
archived用户手动归档只读查看、恢复为草稿、作废
revoked用户作废只读；可选择删除交接目录文件
📌
复制失败（剪贴板异常）时交接单停留 draft，并降级提供"全选手动复制"文本域，不产生虚假的 copied 状态。

3范围界定

3.1 P0：最小完整旅程（本版本必须交付）

覆盖"无 Key 用户要完成一次真实外部协作"所需的闭环：

  1. 交接工作台面板（独立悬浮面板，与现有悬浮球体系一致的显隐设置）；
  2. 6 个高频来源入口：审查 AI 梳理、AI 问一问、专利一键解读、智能比对、阅读器文档问答、分享工作台；
  3. 上下文打包器：自动归集当前软件内数据、勾选、字符统计、超预算分级截断；
  4. 内置指令模板库：覆盖现有全部 AI 功能的 14 类模板（见附录 A）；
  5. 一键复制指令 + 复制前完整预览；
  6. 文件交接区：PDF 落盘到临时交接目录、原生拖出、在文件夹中显示、合并 PDF；
  7. 目标 Agent 档案：1 个通用默认档案 + 3 个预置档案；
  8. 交接台账（localStorage 持久化）；
  9. 结果回传 P0 形态：粘贴保存 + Markdown 预览 + 发送到 AI 分析 Tab / 问一问会话。

3.2 P1：增强能力（下一迭代）

模板编辑器与团队分发自定义模板增删改、JSON 导入导出、团队模板包分发文件
深度链接预填对支持 URL 预填的目标 Agent 生成"打开并预填指令"链接，经 openExternal 唤起
回传结构化解析识别标题/表格/权项演变段落，联动现有 Word 导出（docx）
续聊追问基于历史交接单追加新上下文，生成"追问指令"，保持材料版本一致
脱敏开关申请人/发明人/案号/客户名掩码规则
patent2pic 交接权项图子应用的抽取/重绘/翻译指令交接

3.3 P2：面向未来的演进位

自定义协议回传patentlens://handoff/return?ticketId=... 协议，外部 Agent 页面或浏览器书签可一键回流
双通道自动切换检测内置 API 可用性：有配额走内置 AI，无配额/限流自动提示转交接模式，同一套模板两通道复用
MCP / 本地 HTTP 桥把交接单暴露为受控的本地接口，允许 Trae、Cursor 等支持 MCP/文件访问的 Agent 主动拉取，免去复制
模板效果度量回传质量抽检标注、模板采纳率与返工率统计

3.4 明确不做（防止范围蔓延）

🚫
① 软件后台自动向任何外部 AI 厂商发送数据；② 自动抓取/监听外部聊天窗口内容（外部站点注入、浏览器自动化代操作）； ③ 外部 Agent 账号托管、代登录；④ 以交接模式名义重构现有 AI 功能模块（只做只读复用）。

4核心用户旅程（P0）

4.1 主流程：一次审查意见分析的交接

1
入口发起
在审查看板点击"交接给外部 Agent"，自动带入当前专利与勾选文档
2
核对交接单
模板默认选中"审查意见梳理"，上下文块自动勾选，可增删
3
一键复制
预览完整指令后复制，机密提示条确认
4
拖出 PDF
从文件交接区把 PDF 直接拖进 Agent 聊天上传区
5
外部协作
粘贴指令、发送，在免费 Agent 中获得分析结果
6
回传归档
结果粘贴回交接单，发送到 AI 分析 Tab 查看/导出

4.2 三条关键分支与恢复路径

分支触发条件产品行为
上下文超预算选中块估算量超过目标档案上限预算条变红并置顶提示；按既定优先级自动分级截断，截断处在指令中显式标注；用户可手动取消低优先级块后恢复完整内容
PDF 缓存失效应用重启或会话缓存淘汰，PdfSessionCache 未命中文件载荷标记"已失效"（红色芯片），禁用拖出；提供"重新下载"按钮走现有下载链路，成功后自动恢复
剪贴板写入失败Electron 剪贴板异常或权限问题状态停留 draft；弹出含完整指令的只读文本域，默认全选，用户 Ctrl+C 手动复制
前置数据缺失未查询专利即打开、或未 OCR 却选择 OCR 文本块对应块置灰禁用并说明前置动作（"请先完成该文档 OCR"），不允许带着空块复制

4.3 入口与来源功能的对应关系

从具体功能入口进入时，工作台自动完成三件事：锁定来源功能 → 匹配默认模板 → 预填可用上下文块。用户也可从悬浮球打开空白工作台手工建单。

5功能需求

FR-A 入口与交接工作台 P0

编号需求
FR-A1全局入口：新增"交接"悬浮球打开工作台；显隐设置并入现有悬浮球设置页（参照 float-ball-settings.js 的开关模式），默认开启。
FR-A2场景入口：6 个 P0 来源功能的 AI 按钮旁增加"交接"图标按钮；阅读器文档列表项右键菜单、审查看板文档"更多"菜单同步提供入口。
FR-A3来源感知：场景入口自动锁定来源功能、选中对应模板、预填上下文；全局入口创建空白草稿。
FR-A4工作台布局：三栏结构——左栏交接台账列表、中栏配置区（模板/上下文块/目标档案/预算）、右栏文件交接区；顶部固定指令预览与"一键复制"主按钮。窗口宽度不足时折叠为单栏 Tab。
FR-A5多交接单：支持同时保留多个 draft 交接单，切换不丢失已勾选状态；每个草稿自动保存。

FR-B 上下文打包器 P0

目的：把散落在各 Tab 的数据变成可勾选、可计量、可溯源的标准化上下文，且对业务数据只读不写。

编号需求
FR-B1块目录：支持附录 B 所列全部块类型；每类块声明数据来源（如 currentData、kanbanState、pdfViewState、问一问缓存、分享项目）与默认勾选条件。
FR-B2标准化信封：每个块在指令中以统一格式输出——【块类型｜来源标识｜字符数】标题 + 正文，保证外部 Agent 与回传审阅时可逐块溯源。
FR-B3实时计量：勾选变化时实时统计总字符数，并按中英文混合经验系数估算 token（系数在配置中可调，默认值发布前校准 TBD）。
FR-B4预算与分级截断：按目标档案上限校验；超预算时按固定优先级截断：任务指令 > 当前文档 OCR > 权利要求 > 专利元信息 > 摘要 > 同族/引证 > 说明书。截断处必须插入醒目的截断标记，说明被省略的内容与原因。
FR-B5长文本惯例对齐：说明书等长文本沿用现有软件的截断阈值惯例（如 18000/8000 字段落），保证交接指令与内置 AI 输入口径一致。
FR-B6空态拦截：数据缺失的块置灰并注明前置动作；禁止复制包含空块的交接单。
FR-B7自由备注块：用户可添加自由文本块（如客户特殊要求、关注点），同样计入预算。
FR-B8脱敏（P1）：按掩码规则对申请人、发明人、案号、自定义客户名词表进行替换，替换前后映射仅保留在本地内存、不落台账。

FR-C 指令模板库 P0

编号需求
FR-C114 类内置模板：与现有 AI 功能 1:1 对应（完整映射见附录 A），模板口径直接抽取自现有提示词资产（如 share-ai.js 的四类提示词、comparison-prompts.js 的比对专家提示、翻译/引用分析/文档问答的系统提示），避免两套口径漂移。
FR-C2模板结构：角色设定 → 任务说明 → 上下文占位符 {{blocks}} → 输出格式契约 → 溯源与禁止编造条款。所有模板继承统一的"仅依据输入材料、禁止编造、标注来源"底线条款。
FR-C3变量占位：支持 {{patent_number}}、{{doc_name}}、{{today}}、{{blocks}} 等变量，渲染时以交接单数据替换；未命中变量保留为空并提示。
FR-C4版本管理：模板带 templateId + version；内置模板不可删除，可被用户覆盖；台账记录每次交接使用的模板版本，保证历史交接可复现。
FR-C5编辑器（P1）：新建/编辑/复制模板，变量插入工具栏，JSON 导入导出；团队模板包通过文件分发（与现有分享工作台的文件导入习惯一致）。
FR-C6默认匹配：场景入口按来源功能自动选中模板；用户可在工作台切换，切换后保留上下文块勾选。
✅
单一事实源原则：内置模板文本从现有提示词抽取为模板常量后，内置 AI 与交接模式共用同一口径来源；后续修改提示词必须同步模板版本号，配套契约测试锁定渲染结果。

FR-D 一键复制与目标 Agent 档案 P0

编号需求
FR-D1复制内容：模板渲染后的完整纯文本（Markdown 轻格式兼容），顺序为：角色与任务 → 上下文块（带信封标题）→ 输出契约。通过现有 electronAPI.copyToClipboard 写入剪贴板。
FR-D2复制确认：主进程返回写入结果后才将状态置为 copied；成功后 toast 指引："已复制，请在目标 Agent 聊天窗口粘贴；PDF 请从右侧文件区拖入"。
FR-D3目标档案字段：名称、上下文字符上限、单文件大小上限、接受文件类型、是否支持多文件、深度链接模板、使用备注。
FR-D4预置档案：通用档案（默认，宽松上限）+ ChatGPT 类 + Claude 类 + 国产长文本类（Kimi/豆包/通义/DeepSeek 网页版）。各档案的具体数值发布前实测填写，本文不臆测 TBD。
FR-D5档案可编辑（P1）：用户可复制预置档案自建，并在团队内分享配置。
FR-D6深度链接（P1）：档案配置了链接模板且当前指令长度满足目标限制时，显示"打开并预填"按钮，经 openExternal 唤起；不支持的目标仅保留复制路径。
FR-D7复制留痕：最近 20 条已复制指令可在台账中一键重新复制（从交接单重新渲染，不缓存敏感原文到剪贴板历史之外的位置）。

FR-E 文件交接区（PDF 交接）P0

目的：让审查 PDF 的交接像拖一张图片一样简单，这是本模式区别于"自己复制粘贴"的核心价值点。

编号需求
FR-E1自动归集：按来源功能自动列入文件载荷——审查看板带入当前勾选文档，阅读器带入当前文档；默认勾选已完成 OCR 的文档。
FR-E2落盘交接：主进程新增 IPC，从 PdfSessionCache 读取 PDF 字节（未命中时返回失效状态），写入隔离交接目录 temp/PatentLensHandoff/<ticketId>/，返回本地路径。
FR-E3原生拖出：拖拽文件芯片时经 IPC 调用 Electron webContents.startDrag({file, icon})，用户可直接把真实文件拖入浏览器中 Agent 聊天窗口的文件上传区或系统任意位置。
FR-E4文件夹定位：每个芯片提供"在文件夹中显示"，主进程调用 shell.showItemInFolder。
FR-E5规范命名：文件名格式 专利号_文档类型_日期.pdf，复用 doc-title-recorder.js 的标题记录能力，消除上传后的文件名混乱。
FR-E6合并 PDF：多选后可合并为单个交接 PDF（复用 pdf-lib），适配只接受单文件或拖拽数量受限的目标。
FR-E7文本附件：可将 OCR 文本/选中块导出为 .md 或 .txt 文件放入交接区，适配不支持 PDF 或偏好文本输入的目标。
FR-E8失效恢复：缓存未命中的载荷显示红色"已失效"芯片，禁用拖出并提供"重新下载"，成功后自动恢复为可拖出状态。
FR-E9首次引导：首次使用文件区时显示三步图示：① 复制指令 → ② 拖入 PDF → ③ 发送；不再重复弹出。
FR-E10清理：作废交接单时询问是否同时删除其交接目录；应用启动时清理超过保留期的无人认领文件（保留期 TBD，建议 7 天）。
🔗
为什么能做到"直接拖进浏览器"：Electron 的 startDrag 发起的是操作系统级原生拖拽，载荷为真实文件路径，浏览器的文件上传控件会将其识别为与资源管理器拖入完全相同的 File 对象，无需任何浏览器插件或外部站点配合。

7共享规则与异常

7.1 字符预算与截断规则（全局唯一）

  • 预算口径 = 模板固定文本 + 全部选中块字符 + 自由备注；目标档案上限按字符数配置，token 估算仅作辅助展示。
  • 截断优先级固定为：指令 > 当前文档 OCR > 权利要求 > 元信息 > 摘要 > 同族/引证 > 说明书，任何模块不得自定义顺序。
  • 截断标记统一文案：［…已省略：XX 块后续内容，超出「档案名」上下文预算，可在文件交接区获取完整 PDF／取消低优先级块后重试］。

7.2 文件命名与目录规则

  • 交接目录：app.getPath('temp')/PatentLensHandoff/<ticketId>/，ticketId 全局唯一且不含用户可读敏感信息。
  • 文件命名：专利号_文档类型_日期.pdf；非法字符统一替换为下划线；同名追加序号。

7.3 异常态清单

异常用户可见表现恢复方式
剪贴板失败toast 报错 + 全选文本域手动 Ctrl+C，状态不前进
PDF 缓存失效红色"已失效"芯片重新下载后自动恢复
落盘失败（磁盘/权限）文件区错误提示，工单停留 copied更换保留策略或重试
上下文为空对应块置灰完成前置查询/OCR 后自动启用
超预算预算条变红 + 自动截断标记减选块或更换大预算档案
回传空内容提交按钮禁用粘贴非空内容
台账存储异常顶部提示"本地记录不可用"，不阻断复制本次交接仍可完成，仅无历史

7.4 与现有 AI 功能的边界

交接模式只读消费现有数据与提示词资产，不修改任何现有功能的执行逻辑、缓存结构与 UI 状态；内置 AI 与交接模式是并列通道，不存在互相降级或数据覆盖。
